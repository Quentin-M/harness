# Writing Style

Always-on floor for any text a human reads: chat, code comments, commit messages, docs. The
**Communication** rule shapes replies to Q on top of it.

- **No em-dash.** Use a spaced dash ` - `, a comma, or a full stop. Tilde `~` for soft greetings and
  sign-offs; `…` for a thought trailing off.
- **Lead with the point.** No wind-up, no throat-clearing.
- **Omit needless words.** Active voice, positive form, one idea per sentence.
- **Cut filler.** No "basically", "actually", "in order to", "it's worth noting", "at the end of the day".
- **Be specific.** "Latency dropped 200ms → 40ms", not "performance improved significantly".

## Write the final state

A document reads as if written from scratch with everything known now.

- **No revision scaffolding.** No "corrected", "updated", "revised", "v2", "Status: …", change logs,
  "originally we thought X". State what is true.
- **No back-references.** No "the original proposal said", "previously". A wrong claim is deleted.
- **No apology or self-narration** in an artifact. Chat only.
- An audit trail exists only when Q asks for one.
